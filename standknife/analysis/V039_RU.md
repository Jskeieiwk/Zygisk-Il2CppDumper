# После v0.38: хуки вместо периодического сканирования сцены (предметы, гранаты, бомба)

Статус: код и тест написаны, `tests/world-visuals.cjs` проходит (две мутации теста — без проверки активности и без стартового скана — его
ломают). APK **не собирался**, версия в манифесте/меню **не менялась** (в журнале телефона всё ещё «Cloud v0.38»),
**на телефоне не запускалось.**

## Что показал журнал v0.38 на телефоне (Xiaomi 22111317PG, Android 14)
- `CLOUD:capture-slow totalMs=41..64 … world=40..52 worldScanMs=40..52` — тормозящие кадры целиком состоят из `updateScan`. Скан
  идёт раз в `max(1.5 с, 50 × длительность прошлого)` ≈ 2 с. Скан эффектов ушёл в v0.32 (хук `GrenadeEffectController.Play`), но
  `FindObjectsOfType` для `WeaponDropController`, `DroppedGrenadeController` и `PlantedBombController` остался. Какие именно
  галочки были включены, в журнале не видно; сканируется то, что включено (`Item ESP`, `Grenades`/`Off-screen Nades`/`Grenade Glow`, `Bomb Timer`).
- `gameFps` 21–38 в матче при 4–5 игроках; `cameraMs` 7–8 мс среднее. Это не объясняется одним сканом, правка закрывает только
  периодический скан 40–52 мс.
- Первая попытка: `CLOUD:base-not-found ranges=358 scanBytes=2016317056` и сообщение инжектора «нет подтверждения за 20 секунд». Это не ошибка:
  локатор повторяется каждые 10 с (до 24 раз), следующая попытка нашла базу (`base-found-data … scanBytes=95763568`) и всё поднялось.

## Что изменено
- `assets/world-visuals.js`: общий реестр на вид объектов (`items`, `grenades`, `effects`, `bombs`). Для вида с рабочим хуком:
  один стартовый скан при включении функции (находит то, что уже есть), дальше только регистрация из хука, периодического
  скана нет. Записи проверяются на живость (`Object.op_Implicit`) и на `GameObject.activeInHierarchy` (пул может держать
  объект выключенным; тогда он скрыт, при включении снова виден). Эффекты по-прежнему не сканируются совсем (как в v0.32).
  Вид без хука остаётся на периодическом скане. Выключенная функция ничего не закрепляет.
- `assets/module.js`: хуки на методы из дампа 3.3 (`dump.cs` / `script.json` из `Cloud-project-v23.tar.gz.enc`, libil2cpp.so SHA-256 `45a634d2…2339`):

| Вид | Метод | RVA |
|---|---|---|
| grenades | `DroppedGrenadeController.Awake` | 0x3B0AEEC |
| bombs | `PlantedBombController.Awake` | 0x519E18C |
| items | `WeaponDropController.PreInitialize` | 0x3BEF384 |
| items | `WeaponDropController.Initialize(int,int,int)` | 0x3BF28D0 |

  Для проверки активности: `Component.get_gameObject` 0xA77DD70 и `GameObject.get_activeInHierarchy` 0xA784AC8 (оба из `script.json`).
- Строки журнала: `CLOUD:world-registry-hooks grenades=on bombs=on items=on` (или `scan-fallback`), `CLOUD:world-registered kind=… count=N`.
- `tests/world-visuals.cjs`: новый блок — один стартовый скан, ноль периодических за 80 с, регистрация без дублей, неактивный/
  уничтоженный объект, выключение и повторное включение функции, откат на скан без хука.

## Не проверено
- Что `PreInitialize`/`Initialize` у `WeaponDropController` вызываются для каждого выпавшего предмета (у класса нет `Awake`/`OnEnable`,
  имена остальных методов обфусцированы). Проверка на телефоне: `CLOUD:world-registered kind=items count=…` растёт, когда кто-то роняет оружие.
  Если не растёт — оставить скан для `items` (убрать хук `drop-preinit`/`drop-init`), остальные виды не затрагиваются.
- Что `Awake` вызывается для гранат/бомбы, созданных из пула (объект после повторной активации не проходит Awake). Покрыто тем, что запись уже
  в реестре и проверка активности включит её снова; но объект, впервые попавший в пул до включения функции, найдёт только стартовый скан.
- Выигрыш по кадрам: ожидается исчезновение строк `capture-slow … worldScanMs` с периодом ≈2 с. Замера на телефоне нет.
