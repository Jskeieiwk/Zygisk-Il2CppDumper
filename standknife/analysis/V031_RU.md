# v0.31: убран периодический фриз игры (сканирование сцены для кругов молотова и дыма)

Статус: собрано, 27 локальных тестов проходят. **v0.31 на телефоне не запускалась.**

## Что показал журнал v0.30 (измерено)

Строки `CLOUD:capture-slow` (проход сэмплирования держал поток игры 40+ мс) почти все устроены одинаково:
`world≈worldScanMs`, например `totalMs=51 … world=50 worldScanMs=50`, `totalMs=94 … worldScanMs=87`,
**`totalMs=341 … worldScanMs=306`**. Игроки, эффекты и прицеливание в этих строках занимают единицы миллисекунд.
`worldScanMs` — это `Object.FindObjectsOfType` по сцене, которое раз в 1.5 с запускали для поиска контроллеров эффектов
(круги молотова и дыма). То есть каждые полторы секунды игра замирала на 45–136 мс, а иногда на 300+ мс. Общие пачки
`player-dormant` с `silentMs` 270–510 мс (все враги разом) по времени совпадают с этими фризами. Этот фриз появился вместе с
кругами эффектов (v0.28); в журналах без радиусов `captureMs` макс был 20–70 мс.

В логе лимит 40 строк `capture-slow` исчерпан, поэтому часть более поздних остановок не видна.

## Что изменено

- Контроллеры эффектов теперь регистрирует хук на `GrenadeEffectController.Play` (RVA `0x4D556A8` в дампе 3.3,
  `public void Play(Vector3)`), когда эффект запускается. Пока хук включён, **сцена для эффектов вообще не сканируется**.
  Зарегистрированный контроллер закреплён (GC-handle), каждый раз проверяется на жизнь в Unity так же, как найденный
  сканированием, и забывается через 90 с без нового `Play`. Если хук не поставился, остаётся прежнее сканирование
  (`CLOUD:effect-hook=unavailable, scene scan fallback`).
- Для остальных групп (предметы, гранаты, бомба) сканирование осталось, но пауза между сканами теперь в 20 раз больше
  длительности последнего (от 1.5 до 10 с): дорогое сканирование перестаёт повторяться чаще, чем игра успевает его пережить.
- Журнал: `CLOUD:effect-hook=on` при запуске, `CLOUD:effect-registered controllers=N` при первых регистрациях.

## Проверки

- 27 из 27 тестов. `world-visuals.cjs`: при активном хуке группа эффектов не сканируется ни разу; зарегистрированный
  контроллер даёт круг, уничтоженный пропадает и снимается с закрепления, не игравший 90 с забывается, без хука возвращается
  сканирование; пауза между сканами пропорциональна их стоимости.

## Не проверено

- Что `Play` действительно вызывается для контроллеров молотова и дыма (иначе кругов не будет; тогда в журнале не появится
  `effect-registered`, а `effect-hook=on` будет). Это самое важное, на что смотреть.
- Что общие остановки игры (пачки `dormant`) пропали полностью: часть их могла быть не нашей.
