# v0.22: compiled Canvas primitive batches

The 47-second recording supplied after v0.21 shows Cloud readings mostly
27–35 FPS in a match, and one sampled death-screen frame at 55. Training at
120 FPS is user-reported. The subsequent screenshots show canvas averages
9–16 ms. Video contains no camera/canvas timing trace itself.

`CanvasBatch.java` executes line groups and text commands in ART. Frida
submits their JSON representation with one draw call instead of individual
Canvas/Paint calls for each caption and line group. Special effects, avatar
bitmaps and label-width cache misses still use the Java bridge. This is a
batch helper, not an independent render thread or a Unity renderer.

The loader embeds its compiled dex during build, writes it to the game's
cache as a read-only dex (Android 14 requirement), and loads it using
Java.openClassFile. A successful load logs CLOUD:compiled-canvas-ready.
Load or draw failures log compiled-canvas-unavailable/error and retain the
old renderer for subsequent frames. Device class loading is unverified.

Crash extraction now requires the requested PID. A matching game package
name alone previously admitted stale crash records from PID 9115 while
the current target was 31698. The shown SwipeUpClean is a system kill;
the screenshots do not demonstrate a new SIGSEGV in PID 31698.

Checked: Node suite including preservation of seven players' labels and
geometry in a single compiled submission; Java compilation; crash-extraction
checks; APK signature v2/v3. Actual FPS and Android dex loading require a
device test. Do not claim that the match now reaches 120 FPS.
