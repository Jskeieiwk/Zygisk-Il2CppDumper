# Cloud v0.17: исправления по записи 2026-11-18

На двухсекундной записи водяной знак показывает 22 FPS в начале и 18 FPS после поворота камеры. Без замера игры с выключенным модулем это не позволяет отделить нагрузку игры от накладных расходов ESP.

Подтверждённый дефект в коде: чтение `fire.status()` из визуального кадра вызывало `ensureInstalled()`. Если местный игрок на этот момент не считался актуальным, хуки снимались, а в следующем `Player.LateUpdate` снова ставились. Теперь `status()` только возвращает состояние; установка происходит в игровом шаге, при открытии меню хуки снимаются с сохранением калибровки. Это устраняет показанный в логе цикл `fire-hooks-active` / `fire-hooks-suspended`, вызванный чтением статуса.

При включённом Skeleton v0.16 вызывал native `WorldToScreenPoint` для 16 костей каждого игрока на каждом экранном кадре. Теперь точные кости читаются и проецируются на 10 Гц. Между этими снимками на кадрах камеры точно перепроецируются только голова и позиция ног; остальные экранные точки переносятся относительно этих якорей. Если геометрия непригодна для переноса, выполняется полная проекция. Таким образом скелет остаётся привязанным к движению камеры при меньшем числе переходов JS → native. Быстрый поворот камеры может дать небольшую геометрическую ошибку скелета до следующего полного снимка (не более 100 мс при стабильных кадрах).

Canvas больше не создаёт отдельный Java String для каждого повторного текста и не рисует текст дважды ради тени. Строки кэшируются с ограничением в 128 записей, цвета — в 32; тень текста рисует Paint. Для последующей проверки раз в 10 с журнал пишет `CLOUD:perf` с текущим игровым FPS, средним/максимальным временем обработки кадра камеры и Android Canvas.

Локально прошли тесты и сборка APK с подписью v2/v3. Итоговые FPS и стабильность на устройстве не проверялись. Аудит функций не изменился: 72 из 89 пунктов имеют код, 17 ожидают реализацию.
