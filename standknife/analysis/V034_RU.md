# v0.34: калибровка только по сетевому снимку, дамп кандидатов, «last position» для застывших за стеной

Статус: собрано, 28 локальных тестов проходят. **v0.34 на телефоне не запускалась.**

## Что показал журнал v0.33 (измерено)
- `net-pos-calibrated source=translation offset=0x44 … all=36/36,0/29,0/33,0/0,0/0,7/40,40/40,0/0`.
  Выбран translation+0x44, но он — копия transform: во всех 30 строках `net-pos` `shift=0.00`, и он замёрз вместе с transform.
- snapshot+0x14 (`MovementController+0xB0 → +0x14`) совпадал с позицией в 36 из 36 выборок, но не набрал порог 40.
- Загороженный враг `0x7170928c00`: transform ещё ~1.3 м двигался (−0.26…−1.48 по X), затем стоял без изменений минимум
  18 выборок подряд. Так выглядит экстраполяция после прекращения сетевых обновлений; вероятно, сервер перестаёт присылать
  позицию врага, которого не видно (кроме простреливаемых стен). Это вывод, не доказательство: snapshot+0x14 за стеной не измерен.

## Что изменено
- Выбирать можно только поля снимка (порог 30 выборок); translation читаются только для журнала.
- Пока враг загорожен: `CLOUD:net-pos-obstructed key=.. chosen=.. transform=.. candidates=a | b | …` раз в 500 мс на игрока
  (до 40 строк) — все 8 кандидатов рядом с transform.
- Загороженный враг, чья позиция не меняется 400 мс, помечается как «last position» (как Dormant: полупрозрачный, подпись,
  без экстраполяции движения), вместо «бега на месте».

## Как читать следующий журнал
- В `net-pos-obstructed` первый кандидат (snapshot+0x14) меняется, а transform стоит → позиция есть, ESP поедет за врагом.
- Все кандидаты стоят вместе с transform → клиент позицию не получает; показать его движение нельзя, остаётся «last position».
