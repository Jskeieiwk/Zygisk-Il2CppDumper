# v0.33: позиция загороженных врагов из сетевых данных движения

Статус: собрано, 28 локальных тестов проходят. **v0.33 на телефоне не запускалась.**

## Что показал журнал v0.32 (измерено)
- Хуки `OnObstructed`/`OnUnobstructed` срабатывают для игроков (`CLOUD:occlusion obstructed key=..`), ключи совпадают с
  отслеживаемыми. `SetObstructedVisible(true)` эффекта не дал. Пользователь: враги за стенами «бегут на месте».
- Значит, `LateUpdate` у загороженного врага идёт (он не dormant), скелет анимируется, но transform стоит.

## Гипотеза (из дампа, не измерено)
`MovementController` (`PlayerController+0x108`) хранит `PlayerOcclusionController` (+0xC0): движение, похоже, не применяется к
загороженному игроку. Сетевые данные движения при этом могут продолжать обновляться: снимок `+0xB0` (класс с `Vector3` на
0x14/0x20/0x2C) и данные перемещения `+0x98` (несколько `Vector3`).

## Что сделано
- `assets/net-position.js`: пока враг виден, каждое из 8 полей-кандидатов сравнивается с позицией transform; поле, совпавшее
  (≤0.75 м) в ≥90% из ≥40 выборок, выбирается (`CLOUD:net-pos-calibrated source=.. offset=..`). При равенстве побеждает снимок.
- Пока враг загорожен (состояние по хукам окклюзии), позиция берётся из выбранного поля, кости сдвигаются на ту же разницу.
  Отбрасывается: нечисловое, нулевое, сдвиг >80 м. Журнал: `CLOUD:net-pos key=.. transform=.. net=.. shift=..` (30 строк).
- Если калибровки нет, при загороженном враге в журнал пишутся значения всех кандидатов (`CLOUD:net-pos-uncalibrated`, 20 строк).
- `Reveal Occluded` по умолчанию выключен; журнал окклюзии пишет только смену состояния.

## Как читать следующий журнал
- `net-pos-calibrated` есть, `net-pos … shift` растёт, пока враг бежит за стеной → работает.
- `net-pos … shift≈0` всё время → выбранное поле тоже стоит; сервер, вероятно, позицию не шлёт или она в другом месте.
- только `net-pos-uncalibrated` → ни одно поле не совпало с позицией; смотреть значения кандидатов в этих строках.
