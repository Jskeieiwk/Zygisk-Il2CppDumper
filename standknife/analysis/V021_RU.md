# v0.21: ESP follows camera and current player origins

Changed projection from screen-space skeleton warping to exact projection of
cached world-space bones using a camera matrix snapshot on each game camera
frame. Bone animation still samples at 10 Hz; body translation reads the current
player transform each projection frame. Removed extrapolation from the display
path and the separate 60 Hz projection cap. Android invalidation now requests a
draw directly instead of scheduling an extra animation callback first.

Matrix getters are verified against dump.cs for game 3.3:
worldToCameraMatrix_Injected 0xA727E34, projectionMatrix_Injected 0xA72800C.
At runtime the first visible projection is compared with WorldToScreenPoint;
disagreement disables the matrix path and falls back to native projection.
Successful comparison logs CLOUD:matrix-projection-verified.

Validated: Node tests including live origin refresh between detail samples,
camera rotation, matrix perspective and behind-camera points; APK build/signing.
Not validated on an Android device. Separate Android View/Unity SurfaceView
presentation remains a source of possible display latency. Animated skeleton
poses remain limited by the detail sample rate. Do not claim zero jitter or
120 FPS based on synthetic tests.
