# v0.30: «ESP стоит» — это остановки игры; замеры остановок; остаточная задержка

Статус: собрано, 27 локальных тестов проходят. **v0.30 на телефоне не запускалась.**

## Что показал журнал v0.29 и видео пользователя (измерено)

- Строки `CLOUD:player-dormant` идут **пачками**: сразу 4–8 врагов с одинаковым `silentMs` 310–670 мс, затем столько же
  `player-live` с `silentMs` 2–107. Значит, не конкретные враги выходят из-под обновления, а на 0.3–0.7 с останавливается
  весь главный поток игры (`PlayerController.LateUpdate` не вызывается ни для кого). Это не гипотеза «враг за спиной»:
  в части строк `depth` положительный (враг впереди).
- Видео (35 с, 854 кадра, без разрывов меток времени): серии одинаковых соседних кадров подряд, самая длинная 23 кадра
  (≈0.95 с), ещё 9, 7, 5, 3 кадра. Застывает весь экран, а не только враги. Счётчик FPS игры в видео 14–28
  (запись экрана включена).
- Остановки только отчасти наши: в окнах с пачкой `dormant` `cameraMs` макс обычно 70–180 мс. Но в одном окне
  `captureMs` макс 519 мс, `cameraMs` макс 531 — это точно наш `captureFrame` (сэмплирование раз в 100 мс).
- `lagAvgMs` в журнале 40–75 мс при «задержке по умолчанию 0»: **моя ошибка.** Старое сохранённое значение «1 кадр»
  из v0.28 перекрыло новый ноль, и пользователь играл с лишней задержкой 50–70 мс (кадр на 14–20 FPS). Настройка
  переименована в «Синхронизация ESP, кадры» (`ESP Sync Frames`, ключ новый, значение 0), старое значение не читается.
- Хук камеры при 4–9 игроках и низком FPS: `cameraMs` 6–20 мс (у v0.28 было 4–6): устройство тормозит целиком
  (запись, температура, заряд), всё считается в 3–4 раза медленнее.

## Что сделано

- Переименована настройка задержки, чтобы старое значение не действовало (см. выше).
- `CLOUD:capture-slow totalMs=.. players=.. effects=.. aim=.. world=.. worldScanMs=.. tracked=.. bones=..` — строка пишется,
  когда проход сэмплирования блокирует поток игры 40 мс и дольше (до 40 строк). `worldScanMs` — время сканирования
  сцены `Object.FindObjectsOfType` для кругов молотова и дыма (раз в 1.5 с, пока включены радиусы). Это подозреваемый
  источник 500-мс остановок, но не доказанный.
