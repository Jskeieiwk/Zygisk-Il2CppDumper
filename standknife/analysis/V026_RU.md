# v0.26: один вызов Java на кадр, автоогонь только по прямой видимости

Статус: собрано, 24 локальных теста проходят. **v0.26 на телефоне не запускалась.**

## Что показал журнал и видео v0.25 (измерено на телефоне)

- `players=0`: `canvasMs` 4–9 мс при `gameFps` 16–37, то есть цена кадра не зависит от числа игроков.
  При `players=2` `canvasMs` прыгает от 6 до 20 мс, `cameraMs` макс 100–215 мс. Чистый JS на стенде стоит доли
  миллисекунды (0.25 мс на 5 игроков, на телефоне ≈1 мс), значит основное время — вызовы моста Frida→Java.
- Разбор `screen-overlay.js`: круги (`Draw FOV`, `Custom Scope`), прямоугольники (`Target HUD`, `Hit Logs`, `Kill Flash`)
  и **аватарки игроков** рисовались прямыми вызовами Canvas и Paint через мост, по 4–5 вызовов на каждый круг,
  прямоугольник и каждую аватарку на каждом кадре. Плюс `beginFrame`, `endFrame`, `jstr`, `$dispose`.
- Видео (HUD игры): 20–42 FPS в бою на тренировочной карте. Деревянные стены изрешечены следами пуль.
- Журнал `auto-shot` (новая диагностика v0.25): `limit=3.00m` — ползунок `Wall Thickness` у пользователя на
  максимуме (3 м). Автовыстрелы шли и «сквозь» стены толщиной 0.05–0.32 м, и после них на стенах следы пуль.

## Автоогонь

Из дампа игры: `0x4136838` — это `GunParameters.get_PenetrationPower`, `LossPenetrationPower` лежит в `PlayerHitbox`, есть
`BreakableObjectBase` с порогами пробития. Пробитие в этой игре идёт через игроков и ломаемые объекты. Обычные стены
(деревянные на тренировочной карте) пулю не пропускают, поэтому «толщина стены» — неверный критерий для стрельбы.
Это вывод по именам в дампе и по следам пуль на видео; сам расчёт пробития в игре я не разбирал.

Изменено:
- `Force Shot` и `Silent Aim` действуют только при прямой видимости цели (`fireState.clear`): первый луч до цели
  либо вообще ничего не задел, либо попал в саму цель. Тонкая стена больше не разрешает выстрел.
- `Trigger` с `Autowall` проверяет только прямую видимость.
- `Wall Thickness`, `Autowall` и `Autowall (Aim)` теперь влияют только на то, за какой целью может следовать
  наведение (`Aim assistance`), а не на стрельбу.
- `CLOUD:auto-shot ... reach=direct` по-прежнему пишется на каждый автовыстрел.

Если нужен прежний автоогонь через стены, то нужна проверка, пробивается ли препятствие *на самом деле*
(например, принадлежит ли коллайдер `BreakableObjectBase`). Это отдельная задача: нужно найти способ получить компонент
по коллайдеру в IL2CPP и проверить его в игре.

## Цена кадра

1. **Один вызов Java на кадр** (`CanvasBatch.frame`): запись `Picture`, смещение и обрезка по поверхности игры и
   рисование пакета — внутри одного вызова. Строка передаётся как JS-строка без `jstr`; если мост её не принимает,
   публикатор один раз повторяет вызов с явной Java-строкой и запоминает это (`CLOUD:frame-string-fallback`).
2. **Геометрия поверхности проверяется в Java** на каждом кадре (`setGameSurface`); JS перечитывает её раз в 1.5 с
   как страховку. Если смещение или размер изменились, Java возвращает 0 и кадр пропускается.
3. **Круги, прямоугольники и аватарки — в пакете** (виды 3, 4, 5). Аватарка декодируется в Java один раз
   (`setAvatar`), потом рисуется по номеру. Прямые вызовы Canvas остались только в запасном JS-рендерере.
4. **Ширина текста без вызовов моста**: сумма ширин символов; каждый символ каждого размера измеряется один раз.
5. Телеметрия: строка `CLOUD:native-picture` теперь содержит `renderMs`, `packMs`, `javaMs` (среднее на кадр:
   сборка кадра в JS, упаковка, вызов Java). Это покажет, где остаётся время.

## Проверки

- 24 из 24 тестов. Новые/переписанные: `overlay-bridge-budget.cjs` (настоящие `screen-overlay.js` и хелперы
  `module.js`: в пакетном режиме ни одного обращения к Canvas, Paint или Java при всех включённых функциях и 5
  игроках с аватарками), `overlay-frame.cjs` (ровно один вызов на кадр, откат, переключение на Java-строку),
  `native-picture.cjs` (настоящий разбор пакета в Java-заглушке: все 5 видов примитивов, проверка геометрии
  поверхности, кэш аватарок, откат при ошибке), `text-measure.cjs`, `aim.cjs`, `fire-control.cjs`.
- Мутации (прямой вызов вместо пакета, потеря гейта `clear`) тесты ловят.
- Стенд QuickJS: JS-часть кадра 0.82 мс на 5 игроков, вызовов моста на кадр 0.

## Не проверено

- Реальный FPS и задержка ESP на телефоне, цена одного вызова Frida→Java на этом устройстве.
- Что обёртка Frida принимает JS-строку для параметра `String` (есть автоматический откат).
- Проверка, пробивает ли игра конкретное препятствие (см. выше).

## Если FPS всё ещё низкий

- Нажать «Запустить с V8 (тест скорости)» и прислать журнал: в журнале `CLOUD:runtime=V8`. V8 быстрее
  QuickJS и лучше собирает мусор (в журнале всплески `cameraMs` макс 100–200 мс).
- Прислать строку `CLOUD:native-picture`: `renderMs/packMs/javaMs` скажут, JS это или вызов Java.
