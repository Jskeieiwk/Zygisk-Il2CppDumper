# v0.38: автоволл без толщин, «Все тело», приоритет частей тела, проценты мультипоинтов, хитшанс, автоскоп

Статус: собрано и подписано (`Cloud-StandKnife-root-v38-test.apk`, сертификат `3b0aa238…99f2`, тот же, что у прежних APK),
28 локальных тестов проходят. **На телефоне v0.38 не запускалась.** Сборка — копией `build.sh` из `container-build/` (ecj 3.38.0,
`android-all` API 34, aapt/zipalign/apksigner из apt, `dx --min-sdk-version=24`, лямбды заменены `delambda.py`).

## Запрос пользователя
1. Автовалл: просмотреть все карты, что простреливается, что нет; убрать толщины, просто кнопка.
2. Аим на всё тело сразу: при включённом «все тело» аим стрелял по ногам.
3. В мультипоинты добавить проценты.
4. Мультипоинтам добавить хитшанс, тоже в процентах.
5. Автоскоп.

## Что сделано

### Автовалл: кнопка вместо толщин (частично, см. «Не сделано»)
- Удалены настройки и ползунки `Wall Thickness`, `Wall Count`, `Wall Power`. Сохранённые значения игнорируются.
  Множитель силы пробития остался внутри как константа `WALL_POWER_SCALE=3` (`fire-control.js`), раньше это был ползунок
  `Wall Power` со значением по умолчанию 3. Её не подбирали ни под какую стену.
- `Autowall (Aim)`, `Autowall` и `Wallshot` теперь простые переключатели. Луч идёт насквозь только через преграды, которые
  игра пропускает: **другие игроки** (по `V026_RU.md`: `PlayerHitbox` хранит `LossPenetrationPower`) и объекты, у которых над коллайдером есть
  компонент `BreakableObjectBase` (`assets/wall-rules.js`, вызов `Component.GetComponentInParent`). Всё остальное считается
  стеной, неизвестное тоже. Лимит `MAX_OBSTACLES=4` только ограничивает цикл.
- Выход из преграды больше не ищется обратным лучом: следующий луч стартует на 2 см внутрь пропускаемой преграды, а луч,
  стартовавший внутри коллайдера, его не сообщает повторно.
- Строки журнала: `CLOUD:auto-shot kind=… reach=direct|through=<n> [hitchance={…}]`, `CLOUD:trigger-click … reach=…`;
  `blocked=solid|unknown` лежит в данных решения (`reach.blocked`).

### Хитбоксы
- Новая галочка `Hitbox All` (все тело) в группе hitboxes.
- Причина ног при выбранном теле (из кода v0.37): цель выбиралась по минимальному углу до прицела среди всех точек всех
  выбранных частей. Ноги ближе всего к прицелу на горизонте, поэтому побеждали они. Теперь у каждой части есть ранг:
  список `Приоритет части тела` — «Голова, тело, ноги» (по умолчанию), «Тело, голова, ноги» или «Без приоритета» (старое
  поведение). Часть с худшим рангом берётся только если у лучшей нет точки в дальности, в FOV и видимой. Ноги идут последними.
  Выбор по игрокам по-прежнему идёт по `Aim Priority`.
- Мультипоинты: `Multipoint Scale` 10–100 %, по умолчанию 50. Точки вокруг центра части: голова — вверх/вниз/влево/вправо/
  вперёд/назад; тело — середина, концы оси грудь–таз и боковые точки; ноги — середина бедра–голени и концы.
  Оси считаются по костям (верх: таз→голова, бок: левое бедро→правое бедро). **Размеры хитбоксов в дампе не измерены**:
  радиус головы = 0,6 × |голова − шея| (прежний множитель макушки), ширина тела = половина расстояния между бёдрами.
  Это не откалибровано, процент как раз для подбора.
- Хитшанс: галочка `Hitchance` и `Hitchance Percent` 1–100, по умолчанию 60. Хитшанс считается как доля точек полного
  облака части (100 %), до которых доходит линия (с учётом автоволла, если он включён для этого режима); берётся лучшая
  из выбранных частей. **Это видимость цели, а не разброс оружия** (разброс не измерен). Ниже порога `Trigger`, `Force Shot`
  и `Silent Aim` не стреляют; наведение (`Aim assistance`) порогом не ограничивается.
- Кости: при `Multipoints`/`Hitchance` читаются шея, таз и бёдра (`aimBones`), иначе только центры выбранных частей.

### Автоскоп
- В меню на странице aim, группа «aim assistance». Раньше строка была в «knife bot» и помечена `missing`.
- Бит кнопки прицела в команде игры **неизвестен**. Он определяется по вашим собственным прицеливаниям: при каждом открытии
  прицела байты команд за последние 500 мс пересекаются с предыдущими раскрытиями (байт огня 0 исключается). После трёх
  раскрытий с единственным общим байтом он считается кнопкой прицела (`CLOUD:scope-calibrated mask=… samples=3`).
  Поэтому **сначала откройте прицел снайперки вручную три раза**.
- Потом, если в руках снайперка (id 51–54, как и в `Sniper Crosshair`), прицел закрыт и у наведения свежая цель, байт
  нажимается как клик 80 мс, повтор не раньше 500 мс. Если после двух кликов прицел не открылся — пауза 1,5 с и
  `CLOUD:auto-scope-gave-up`. Строки `CLOUD:auto-scope click n=…` — не более 30.
- Автоскоп входит в Safe Mode (выключается вместе с автоматической стрельбой).

## Измерено по дампу 3.3 (dump.cs/script.json из `Cloud-project-v23.tar.gz.enc`, libil2cpp.so SHA-256 `45a634d2…2339`)
- `Axlebolt.Standoff.Game.BreakableObject.BreakableObjectBase`, Assembly-CSharp, TypeDefIndex 3857 (dump.cs, строка 317347).
  Поля: `_hitCollider` 0x40, `_minPenetrationValueForCoeff` 0x48 (float), `_minBreakPenetrationValue` 0x4C (float),
  `_minBreakWeaponHitDistance` 0x50.
- `UnityEngine.Component$$GetComponentInParent(Type, bool, MethodInfo)`: RVA `0xA77E4E0` (script.json).
- Эти значения записаны в `WALL_RULES`. Пороги 0x48/0x4C только пишутся в журнал (`CLOUD:wall-rules breakable minBreak=… minCoeff=…`,
  до 40 строк): как они соотносятся с силой пробития оружия (`WeaponParameters+0x1A4`), в дампе не видно, решения по ним нет.
- Команда игры `CHCEGCBBDDFHDCD` — шесть `bool` (0x0–0x5) с обфусцированными именами, байт кнопки прицела по именам не определить,
  поэтому автоскоп остаётся с обучением по вашим открытиям прицела.

## Не сделано и почему
- **«Просмотреть все карты».** Данных карт с материалами нет (`colliders_out.rar`, `geometry.bym` материалов не содержат, и самих
  файлов нет в релизе). Классификация делается в игре по компоненту `BreakableObjectBase`, поэтому она одинаково работает на всех картах,
  но **ни на одной карте не проверена**. Полный обход сцены (`FindObjectsOfType`) не добавлялся: в v0.28–v0.30 такой скан давал фризы 45–306 мс.
- Пороги `BreakableObjectBase` не сравниваются с силой пробития (см. выше). Если после теста окажется, что часть объектов не пробивается,
  значит порог нужно учесть; для этого и пишутся строки `minBreak`/`minCoeff`.
- Старый `zusa99.zip` из релиза повреждён (дыра из нулей 127 926 272–150 994 944 байт); рабочий дамп лежит в `Cloud-project-v23.tar.gz.enc`.

## Что проверить на телефоне
1. `Hitbox All` + `Hitbox Priority = Голова, тело, ноги`: аим не уходит в ноги, пока видны тело или голова.
2. `Multipoints` с разными `Multipoint Scale`: точки не должны выходить за модель.
3. `Hitchance`: в `CLOUD:auto-shot … hitchance={"aim":…,"crosshair":…}` проценты разумные при частичном укрытии.
4. Автоскоп: три ручных прицеливания, строка `scope-calibrated`, затем `auto-scope click`. Если `gave-up` — байт
   выбран неверно, пришлите журнал.
5. Автовалл: `reach=through=…` в журнале; строки `wall-rules breakable minBreak=…` показывают, какие объекты признаны ломаемыми.
   Если автовалл стреляет в сплошные стены, пришлите журнал и видео.
