# Cloud Oxide External v0.30 — handoff for another AI

This file is the current source of truth. Files in `history/` describe older releases and contain stale claims.

## Current state

- Android APK package `com.cloudcrack.oxide.external`, versionCode 30. UI and overlay: Java. Root backend: C++17 ARM64. **No Rust implementation.**
- The app requests overlay permission and root, launches Oxide 12034, draws a separate overlay, and starts `libexternal.so` via `su`. Backend uses `process_vm_readv/writev`; it does not inject into the game.
- Latest user report: **only the cheat app/overlay closes automatically**. v0.30 keeps its launcher Activity in the task and writes `last-run.log`; `MainActivity` has a **Copy crash log** button. There is no returned v0.30 log yet, so the cause is unresolved. Do not claim it is fixed.
- User was also concerned APK size. v0.29+ includes exactly 2 MiB of inert `assets/size-padding.bin`, generated by `build.sh`; it does not affect functionality. Be transparent about it.
- ESP and aimbot have **not** been verified in a live match on the user's device. Compilation, signing, and local calculation tests do not prove game behavior. Earlier screenshots confirmed an overlay and lobby statuses only.

## Source layout

- `android/src/.../MainActivity.java`: overlay permission, root/start sequence, launcher and crash log button.
- `android/src/.../OverlayService.java`: foreground service, menu, configuration, backend output parser, overlay windows.
- `android/src/.../EspView.java`: FOV/crosshair and ESP rendering from `MATRIX`, `FRAME`, `BONES`, `WORLD` lines.
- `android/src/.../DiagnosticLog.java`: bounded persistent last run log and Java uncaught exception handler.
- `native/main.cpp`: root backend, exact game Build ID check, IL2CPP class lookup, player/world reads, camera and aim, freecam, farm/heal.
- `native/ballistics.h`: bullet interception, locally tested.
- `tests/`: host calculations tests. `legacy_internal/`: older internal implementation for reference only; not part of current APK.
- `inputs/`: Oxide 12034 reference dump and game libraries for analysis; **not** packaged in the APK.
- `build/debug.jks`: debug signing key used for the distributed APK. Preserve it to allow installs over v0.30. This is not a production signing key.

- Aim requires a readable FPHitscan weapon profile and valid camera matrices; diagnostic status `AIM waiting_weapon_profile` etc. identifies gating. A `write_ok` status only proves `process_vm_writev` returned success, not that aiming behaved correctly in game.
- Native class/field offsets and Unity camera matrices are candidate layouts from the dump/binaries. Several paths are untested on device. Crash/root cause should be investigated before claiming full functionality.

## Build

Requires JDK 21, Android SDK platform 35/build-tools 35.0.0, Android NDK r27c, `zip`, Python 3. Set `JAVA_HOME`, `ANDROID_SDK_ROOT`, `ANDROID_NDK_HOME`, then run `bash build.sh` from this directory. Output: `dist/Oxide_12034_external_v30.apk`. Build does not use `inputs/` or `legacy_internal/`.
