# Rust payload — skeleton

Fully internal Rust port of the in-process cheat module. The ptrace loader
stays C++ (reused from `../project/native/injector.cpp` — small, verified,
and swapping it is a separate risk). Everything that lives inside the game
process is now Rust: boot thread, Build ID / signature verification, IL2CPP
API table, Dobby hook on `PlayerManager::LateUpdate`, internal state, menu
(drawn via IL2CPP calls into Unity, no Java), feature dispatch.

## Build

Prerequisites:
- Android SDK + NDK r27 (set `ANDROID_NDK_HOME` or let `build.sh` use the
  default `$ANDROID_SDK_ROOT/ndk/27.2.12479018`).
- `rustup` installed. `build.sh` adds the `aarch64-linux-android` target.
- `cmake` + a host C++ toolchain (same as the original `project/build.sh`).

```
cd project_rs
bash pack.sh
```

Outputs `dist/update_<rand5>.sh` — self-extracting, signed only by its
contents. Verify extraction without running:

```
sh dist/update_<rand5>.sh --verify
```

## What is wired end-to-end

- ELF `.init_array` constructor (`#[ctor]`) spawns a boot `pthread`.
- Boot polls `dl_iterate_phdr` for `libil2cpp.so`, verifies the GNU Build ID
  against `shared::TARGET_BUILD_ID`, and matches two anchor instructions.
- Boot calls `dobby::hook(PLAYER_LATE_UPDATE)` with the Rust
  `late_update` function; the original callable is stored in
  `ORIGINAL_LATE_UPDATE`.
- On the first managed-thread tick, `initialize_from_main_thread` fills the
  IL2CPP API table and flips `READY`. Every subsequent tick runs the original
  `LateUpdate`, then features, then menu.
- Logcat lines use the per-build `BRAND_TAG`, 1–3 letters.

## Verification done in-container

**NOT built**: no Android NDK is installed in this container. The code
has been type-checked by hand against the Rust 1.80 + ndk-sys/libc/parking_lot
API, and every unsafe FFI boundary has a matching declaration. Compile the
tree on your build host and report any mismatch — this is the first point to
iterate.

Known hygiene:
- `panic = "abort"` set workspace-wide so no panic can leak into Unity main.
- `strip = "symbols"`, `lto = "fat"`, `opt-level = "z"`, `codegen-units = 1`
  in the release profile.
- Linker flags mirror the C++ UNDETECT.md pass: `--build-id=none`,
  `--gc-sections`, `--exclude-libs,ALL`, `-z,relro,-z,now`.

## Residual risks that did NOT move with the C++ pass

- `DobbyHook` still rewrites `.text` at `PLAYER_LATE_UPDATE`. The documented
  next step is `MethodInfo::methodPointer` swap. In Rust it lands as
  `il2cpp::patch_method_pointer(method: *mut Method, replacement: *mut c_void)`
  and the field offset inside MethodInfo needs to be pinned for this Build ID.
- Rust `.so` still lands on disk at `/data/user/N/<pkg>/code_cache/` with the
  randomised prefix from `shared::BRAND_LIB_PREFIX`, then unlinks after
  `dlopen` (same behaviour as the C++ loader — the loader was not rewritten).
- The hitsound playback path is not ported; the headshot sound is silent
  until `features::hitsound` is wired through a Dobby hook on
  `UnityEngine.AudioSource::PlayOneShot`.
- Menu text rendering through `UnityEngine.GUI::Label` needs a `GUIStyle` kept
  alive across frames — otherwise GC collects the style and the label panic
  on the next call. Allocate once in `initialize_from_main_thread`.
